# Planning 与 ReAct 优化

参考教程第 2 章和第 10 章，将执行流程补成：制定计划 → 按依赖执行 → 对照真实结果验收 → 只补未完成部分。

## Planning

- 计划明确最终交付、每步验收和依赖；支持前向依赖，执行前统一排序。依赖成环、缺失、编号重复或超过 8 步时拒绝整份非法计划，避免悄悄漏做。
- 保留完整业务描述和验收条件；界面仍展示简短进度。计划审查参考历史中已确认的口径及当前可用能力。
- 步骤失败先局部补做一次；初轮结束后最多再调整一次未完成步骤。已成功的独立步骤不重做，依赖未通过的步骤保持阻塞。
- 补做保留原目标、验收、依赖、真实证据及已发现问题。验收曾明确失败时，必须重新验收通过，超时或一句“已完成”不能抹掉失败。

## ReAct

- 计划、局部补做和最终核对共用工具预算，恢复次数跨同一步补做保留。重复读取相同版本数据且没有新结果时及时停止。
- 相同代码和相同输入版本的成功脚本复用原结果；原样失败最多实际执行两次。输入表版本或原件内容变化后允许重新执行。
- 完成必须有匹配当前目标的真实证据。步骤只能引用自身、明确依赖或显式复用的原始成果；未执行的回执和无关步骤结果不能证明完成。
- 需要全量数据的任务，必须有完整数据处理证据；局部预览和未知完整性不能替代全量结果。
- 修复重复工具调用编号、异常时丢失真实观察及同批调用在等待用户后继续执行的问题。界面只显示执行进展，不输出内部推理。

## 验证

使用 `backend/.venv/bin/python -m pytest backend/tests -q` 运行后端回归。新增测试覆盖依赖顺序、有限补做、原验收保留、证据范围、全量数据、脚本复用、预算和异常恢复。测试使用本地可控模型返回，验证执行规则；真实模型在业务数据上的效果仍需实际任务评估。

主要入口：`agent/planner.py`、`agent/plan_progress.py`、`agent/thinking.py`、`agent/executor.py`、`agent/completion.py`。
